# 项目收尾任务清单

## 1. 清单目标

本清单用于梳理当前项目在核心功能基本成型之后，距离课程最终交付仍需完成的收尾工作。

当前项目已经具备以下基础：

- RAG 核心链路已实现
- DeepSeek 调用链路已接入
- 向量库与检索能力已具备
- Web 前后端主链路已初步跑通
- AI 生图提示词优化网站原型已完成

因此，后续重点不再是继续扩展底层能力，而是补全课程要求、完善交付质量、准备最终提交材料。

---

## 2. 收尾任务总览

当前建议重点完成以下 12 项收尾工作：

1. 完成对比实验模块
2. 决定是否补 CLI
3. 跑通完整主流程自测
4. 清理配置与敏感信息
5. 完善 README
6. 补页面设计交付说明
7. 生成实验测试样例
8. 做实验截图
9. 写实验分析内容
10. 检查项目结构与命名
11. 做最终回归测试
12. 打包提交

---

## 3. 详细任务清单

### 3.1 完成对比实验模块

目标：

- 补全 `src/compare.py`

需要实现：

- 仅 LLM 模式
- 仅检索模式
- RAG 模式
- 对同一输入统一输出三组结果

交付标准：

- 至少能对 3 个测试输入给出完整对比结果
- 结果适合截图和写实验分析

当前状态：

- 未完成

---

### 3.2 决定是否补 CLI

目标：

- 判断是否需要实现 `src/ui.py`

建议：

- 如果课程明确要求 CLI，则补一个最小可用版本
- 如果 Web 界面已足够支撑课程展示，则 CLI 可以只实现简版

CLI 最低建议能力：

- 输入提示词
- 输出优化结果
- 输出来源片段

当前状态：

- 未完成

---

### 3.3 跑通完整主流程自测

目标：

- 确认当前项目不是“代码存在”，而是“可以稳定运行”

检查项：

- `.env` 配置是否正确
- `data/` 中知识库文件是否有效
- 向量库是否能构建
- `/api/status` 是否返回正常
- `/api/optimize` 是否返回正常
- 首页是否能真实返回优化结果

交付标准：

- 至少完成一轮从启动到优化输出的闭环验证

---

### 3.4 清理配置与敏感信息

目标：

- 避免提交时暴露敏感信息

检查项：

- `.env.example` 中不得保留真实 API Key
- README 中不要写死本地绝对路径
- 不提交无关日志、缓存和临时文件

交付标准：

- 仓库可安全公开或交作业提交

---

### 3.5 完善 README

目标：

- 让他人可以根据文档独立复现项目

README 至少应补齐：

- 项目简介
- 功能说明
- 技术栈
- 目录结构
- 安装步骤
- `.env` 配置说明
- 启动命令
- Web 使用方式
- 数据准备说明
- 常见问题

交付标准：

- 新读者无需额外询问即可运行项目

---

### 3.6 补页面设计交付说明

目标：

- 让“页面设计”部分成为完整交付物

建议整理：

- 页面设计说明
- 首页结构说明
- 交互流程说明
- 设计截图或原型截图

交付标准：

- 可支撑“页面设计”部分的答辩或文档展示

---

### 3.7 生成实验测试样例

目标：

- 为后续截图和实验报告准备标准输入

建议至少准备以下 3 类样例：

- 人物类提示词优化
- 场景类提示词优化
- 产品海报类提示词优化

建议每类包含：

- 原始提示词
- 优化目标
- 目标平台
- 预期改进方向

---

### 3.8 做实验截图

目标：

- 满足课程提交对截图材料的要求

建议截图内容：

- 首页默认态
- 输入提示词后的成功态
- 检索依据展示区
- 对比实验页
- 知识库状态或刷新结果

交付标准：

- 至少 3 组以上清晰截图

---

### 3.9 写实验分析内容

目标：

- 为实验报告提供正文素材

至少应说明：

- 为什么选择 AI 生图提示词优化作为应用场景
- RAG 在提示词优化中的作用
- 优化前后差异
- 相比直接生成的优势
- 当前方法的局限

交付标准：

- 可直接用于撰写课程报告正文

---

### 3.10 检查项目结构与命名

目标：

- 提高最终提交版本的整洁度

检查项：

- 是否存在废弃文件
- 是否存在重复原型
- 文件命名是否统一
- `src/` 下入口是否清晰

交付标准：

- 项目目录清晰，结构合理，便于审阅

---

### 3.11 做最终回归测试

目标：

- 提交前做最后一轮全面验证

测试内容：

- 安装依赖是否成功
- 启动 FastAPI 是否成功
- 首页是否能打开
- 优化按钮是否可用
- 知识库刷新是否可用
- 异常输入是否有提示

交付标准：

- 提交版本具备基本稳定性

---

### 3.12 打包提交

目标：

- 形成最终课程交付物

整理内容：

- 源代码
- `requirements.txt`
- `README.md`
- 页面设计文档
- 实验截图
- 实验报告
- 必要的数据说明

交付标准：

- 最终压缩包可直接提交

---

## 4. 推荐执行顺序

建议按以下顺序推进：

1. 完成 `compare.py`
2. 决定是否补 `ui.py`

4. 做完整主流程自测
5. 清理敏感信息与无关文件
6. 准备实验样例
7. 做截图
8. 写实验分析
9. 做最终回归测试
10. 打包提交
