# Step 16 页面设计交付说明

## 目标

将已有的 Web 方案整理成可直接用于课程答辩和最终提交的交付说明，明确当前页面承担的展示职责、交互流程和截图建议。

## 当前交付范围

- Web 主入口：`src/deepseek_rag_homepage_prototype.html`
- FastAPI 后端：`src/api_app.py`
- Streamlit 备用演示入口：`src/web_app.py`
- 页面设计方案原文：`ai_deliverables/step-15-Web页面设计方案.md`

## 页面职责

- 首页负责展示提示词优化主流程
- `/api/status` 提供运行状态、知识库状态、模型状态
- `/api/optimize` 返回优化结果、来源文档与检索片段
- `/api/rebuild-kb` 提供知识库重建入口

## 页面结构说明

- 顶部区域：项目名称、模型状态、知识库状态
- 左侧状态区：文档数量、向量库数量、模型参数
- 中间主区：原始提示词输入、平台/风格/目标配置、优化结果
- 结果区：优化后的提示词、说明、来源列表
- 证据区：Top-K 检索片段及对应来源

## 交互流程说明

1. 页面加载时请求 `/api/status`
2. 用户输入原始提示词并提交
3. 后端检索知识库相关片段
4. 后端调用 DeepSeek 生成优化结果
5. 页面展示优化结果和来源证据

## 对比实验交付方式

当前仓库未单独实现第二个可视化对比页面，改为以下可交付形式：

- `src/compare.py` 负责生成三模式对比结果
- `src/ui.py --mode compare` 提供命令行对比展示
- `ai_deliverables/step-16-对比实验结果.md` 用于报告截图和实验分析引用

这种实现仍满足“同一输入下展示 LLM-only / Retrieval-only / RAG 三种结果”的课程要求，同时降低前端返工成本。

## 截图建议

- 首页默认状态
- 输入提示词并返回优化结果后的状态
- 检索片段展开后的证据区域
- 三模式对比结果页或对比结果 Markdown

## 当前限制

- 首页 HTML 原型仍建议后续再做一次细节文案清理
- 对比实验暂未做成独立 Web 子页面
- 截图需要在本机启动服务后手动或半自动采集
