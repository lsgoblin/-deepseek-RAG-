# Web 页面设计方案

## 1. 设计目标

本页面定位为课程项目演示型 RAG 网站，核心目标不是营销展示，而是让用户和老师快速看懂完整链路：

`输入问题 -> 检索知识 -> 生成回答 -> 展示来源`

页面设计需要满足以下目标：

- 一眼看懂系统用途
- 提问流程顺畅
- 检索证据展示清楚
- 风格简洁、有技术感、适合截图交作业

---

## 2. 页面整体结构

建议先设计为 `1 个主页面 + 1 个扩展页面`。

### 2.1 主页面：智能问答

主页面承担项目核心展示任务，建议包含以下区域：

- 顶部导航区
- 左侧状态区
- 中间问答主区
- 下方证据区

### 2.2 扩展页面：对比实验

扩展页面用于课程报告和实验截图，展示以下三种模式：

- 仅 LLM
- 仅检索
- RAG

目标是让用户能对同一问题的三种结果进行横向对比。

---

## 3. 主页面设计方案

主页面采用左右加上下的混合布局，突出问答主流程。

### 3.1 顶部区域

展示内容：

- 项目标题：`DeepSeek RAG 智能问答系统`
- 一行说明：`基于本地知识库检索与生成的课程项目演示`
- 右上角状态标签：当前模型名、知识库状态

设计目标：

- 页面打开后，用户立即理解系统用途
- 顶部信息简洁，不占用过多垂直空间

### 3.2 左侧边栏

展示内容：

- 知识库状态
- 已加载文档数量
- 当前向量库状态
- 当前模型与参数摘要
- `构建/刷新知识库` 按钮
- 示例问题快捷入口（可选）

设计目标：

- 用于承载系统状态和辅助操作
- 不干扰主要问答流程

### 3.3 中间主区上半部分

展示内容：

- 大号问题输入框
- 主按钮：`开始提问`
- 次按钮：`清空`
- 提示文案，例如“请输入与你的知识文档相关的问题”

设计目标：

- 输入区足够醒目
- 用户无需学习即可开始使用

### 3.4 中间主区中部

展示内容：

- `最终答案` 卡片
- 答案正文
- 生成状态提示
- 来源标签区

设计目标：

- 将最终答案作为视觉中心
- 确保回答结果清晰可读

### 3.5 中间主区下部

展示内容：

- `检索片段` 区域
- 每条片段做成折叠卡片
- 展示来源文档名、chunk 序号、相似度、正文片段

设计目标：

- 体现 RAG 系统“先检索、后生成”的特点
- 让老师能够看到可溯源证据

### 3.6 底部辅助区

展示内容：

- 错误提示
- 系统消息
- 空结果提示

例如：

- API Key 缺失
- 知识库为空
- 未检索到有效内容

设计目标：

- 明确系统状态
- 减少使用过程中的理解成本

## 5. 视觉风格建议

建议走 `学术工具型 + 轻科技感` 路线，不做花哨官网风格。

### 5.1 配色建议

- 主背景：`#F6F8FB`
- 卡片背景：`#FFFFFF`
- 主色：`#1565C0`
- 强调色：`#0F9D58`
- 警告色：`#D93025`
- 文本主色：`#1F2937`
- 辅助文本：`#6B7280`

### 5.2 字体建议

- 中文：`Noto Sans SC` 或 `思源黑体`
- 英文与数字：`IBM Plex Sans` 或 `Inter`
- 标题使用较高字重
- 正文保持中等字重
- 辅助信息使用较浅颜色和较小字号

### 5.3 样式建议

- 卡片圆角：`12px`
- 边框颜色浅灰
- 阴影轻量化，不要过重
- 主按钮高对比度
- 次按钮低饱和
- 模块留白统一
- 检索片段使用分组卡片，避免内容堆叠

---

## 6. 组件设计建议

建议统一以下组件规范：

- 输入框：高可见、支持多行
- 主按钮：用于提问
- 次按钮：用于清空或辅助操作
- 状态标签：已就绪、构建中、失败
- 答案卡片：页面视觉中心
- 证据卡片：支持折叠展开
- 来源标签：小型圆角标签
- 错误提示条：高识别度但不过度刺眼
- 空状态卡片：用于默认态和空结果态

---

## 7. 交互状态设计

页面至少应包含以下 5 种状态：

### 7.1 默认态

- 尚未提问
- 页面展示说明文字和示例问题

### 7.2 加载态

- 用户点击提问后
- 页面显示“正在检索并生成答案...”

### 7.3 成功态

- 显示最终答案
- 显示来源
- 显示检索片段

### 7.4 空结果态

- 没有命中相关内容
- 提示“根据现有资料无法回答”

### 7.5 错误态

- API Key 缺失
- 知识库为空
- 模型调用失败
- 依赖缺失

---

## 8. 第二页面：对比实验

该页面专门服务课程实验与报告截图。

### 8.1 页面目标

展示同一个问题在三种模式下的输出差异：

- 仅 LLM
- 仅检索
- RAG

### 8.2 推荐布局

- 顶部：问题输入区
- 下方：三列结果卡片
- 页面底部：简短结论摘要

### 8.3 设计价值

- 便于截图
- 便于实验分析
- 能体现 RAG 在准确性和可溯源性方面的优势

---

## 9. 第一阶段推荐交付物

第一版建议先输出以下设计成果：

- 首页线框图
- 首页高保真稿
- 对比实验页线框图
- 一页简单样式规范

这些内容已经足够指导后续开发和页面实现。

---

## 10. 推荐执行顺序

建议按以下顺序推进页面设计工作：

1. 明确页面目标
2. 列出页面模块
3. 绘制首页线框图
4. 确定视觉风格
5. 设计交互状态
6. 输出高保真稿
7. 再进入前端或 Streamlit 实现

---

## 11. 一句话总结

这套页面设计方案的重点不是做复杂网站，而是做一个结构清晰、展示完整、适合课程项目答辩和截图提交的 RAG 问答演示页面。
