# OpenAI API：图像生成与可控参数

来源：<https://developers.openai.com/api/docs/guides/image-generation?utm_source=chatgpt.com>  
整理时间：2026-04-22  
用途：沉淀“写好提示词之外，如何通过接口参数提升生成结果”的知识点，适合和提示词方法论一起进入知识库。

## 核心结论

OpenAI API 文档说明了两件事：

1. prompt 决定你想要什么。
2. 接口参数决定你以什么精度、尺寸、格式和编辑方式得到它。

因此，知识库里不能只存“怎么写 prompt”，还要存“生成参数怎么配”。

## 与提示词相关的关键知识点

### 1. Responses API 会自动改写提示词

在 Responses API 中使用图像生成工具时，主模型会先根据你的输入生成一个优化后的 `revised_prompt`。这意味着：

- 用户原始提示词可以先偏业务表达
- 系统可以读取改写后的版本做调试和分析
- 如果结果不稳定，可以比较“原 prompt”和“revised_prompt”的差异

这对知识库建设很重要，因为它支持后续做 prompt 评估、归因和模板优化。

### 2. 输出尺寸会影响构图效果和生成成本

文档提供了常用尺寸示例，例如：

- `1024x1024`：适合方图
- `1536x1024`：适合横版
- `1024x1536`：适合竖版

如果需求是海报、封面、移动端头图、商品详情图，尺寸本身就是 prompt 外的重要控制项。知识库应把“应用场景 -> 推荐尺寸”作为结构化经验保存下来。

### 3. 质量等级决定速度与精度的平衡

API 支持 `low`、`medium`、`high`、`auto` 等质量等级。文档建议：

- `low`：适合草稿、缩略图、快速试错
- `medium` / `high`：适合最终成品、细节要求高的画面

如果是小字较多、人物特写、密集信息图、身份敏感编辑、高分辨率输出，应该优先评估更高质量等级。

### 4. 输出格式和压缩影响实际交付

文档说明：

- 默认输出为 `png`
- 也可以请求 `jpeg` 或 `webp`
- `jpeg` 在延迟敏感场景下更快
- `jpeg` / `webp` 可配合压缩率控制体积

这部分对产品化很有价值，因为“生成质量”和“交付效率”常常需要一起考虑。

### 5. 编辑场景要善用参考图与掩码

API 支持：

- 直接生成新图
- 使用一张或多张参考图生成新图
- 上传原图 + mask，只编辑局部区域

对知识库来说，这意味着可以沉淀三类编辑提示词模板：

- 纯文本生成模板
- 参考图生成模板
- 局部重绘模板

### 6. 局部编辑时，掩码要求必须纳入知识库

文档明确指出：

- 原图与 mask 必须尺寸一致
- 二者格式一致
- mask 需要带 alpha 通道

这类内容虽然不是 prompt 写法本身，但属于“提示词生效前的前提条件”，如果不入库，后续很容易踩坑。

### 7. 输入保真度会影响编辑稳定性

文档指出，`gpt-image-2` 在处理输入图片时默认采用高保真模式，因此在编辑和参考图工作流中，更适合做“保持主体特征、局部调整内容”的任务。

这意味着，当用户需求是：

- 保持人物长相不变
- 保持商品外观不变
- 保持 UI 结构不变

就应优先使用“参考图/编辑工作流 + 明确保持项”的写法，而不是重新从零生成。

## 适合沉淀到知识库的规则

### 规则一：写 prompt 时同时写清输出参数

除文字描述外，至少要同步考虑：

- 尺寸
- 质量
- 输出格式
- 是否需要背景透明或自动背景

### 规则二：先低成本试错，再高质量出图

推荐流程：

1. 用 `low` 快速试多版构图和风格
2. 确认方向后切到 `medium` 或 `high`
3. 对最终稿再决定 `png`、`jpeg`、`webp`

### 规则三：涉及编辑时，prompt 不能只说“想改成什么”

还应该补充：

- 参考哪张图
- 哪些区域允许改动
- 哪些要保持不变
- 是否需要用 mask 做局部控制

这篇资料适合成为“提示词工程参数层”的基础文档。它补足了纯提示词方法论常缺失的部分：

- 尺寸与画幅控制
- 质量与成本取舍
- 接口输出格式选择
- 掩码编辑前提
- 参考图和多图工作流
- `revised_prompt` 的调试价值
