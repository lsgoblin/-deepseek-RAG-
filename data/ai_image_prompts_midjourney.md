用途：沉淀 Midjourney 对“提示词应该怎么写得更清楚”的基础方法，适合作为面向创意探索场景的知识库内容。

## 核心结论

Midjourney 的思路和很多“超长指令流”不同。它更强调：

- 用清晰短语表达核心画面
- 优先描述想要的结果
- 少写啰嗦命令，多写具体视觉对象

## Prompt Basics 的关键原则

### 1. prompt 就是你对画面的直接描述

Midjourney 把 prompt 定义为告诉系统“你想看见什么”的文本或短语。它可以很短，甚至是单词，但如果你希望输出更独特、更稳定，就需要更认真地选择词语。

### 2. 短而清晰的 prompt 往往更有效

Midjourney 明确建议：短而简单的 prompt 经常能生成更好的图。原因不是“越短越强”，而是长串命令、解释型口语和堆叠清单容易让画面重心分散。

更好的做法是：

- 先用一句话概括画面核心
- 再加少量真正重要的风格或构图信息
- 避免无意义的修辞和重复命令

### 3. 词要准，不要泛

Midjourney 特别强调选词质量。相比“大”“好看”“有感觉”这类模糊词，更有效的是：

- 更精确的名词
- 更具体的形容词
- 明确数量
- 更清楚的集合词

例如，与其写“cats”，不如明确“三只猫”；与其写“birds”，不如写“一群海鸥”。

### 4. 描述你想要什么，而不是你不想要什么

Midjourney 明确提醒：如果 prompt 中提到某个元素，即使你写的是“不要这个元素”，系统也可能仍然把它生成出来。  
因此基础 prompt 应优先正向描述目标画面。

如果一定要排除某些元素，应使用专门的参数机制处理，而不是在自然语言里反复写否定句。

### 5. 细节越少，变化越大；细节越多，控制越强

Midjourney 的一个核心平衡点是：

- 简短 prompt：创作空间更大，结果变化更多
- 详细 prompt：输出更可控，但风格弹性变小

这意味着知识库里应保存一条重要经验：

如果用户目标是“找灵感”，就从短 prompt 开始；  
如果用户目标是“复现脑海中的具体画面”，就补足关键细节。

### 6. 不要把 prompt 写成需求文档

Midjourney 更擅长接收“视觉描述”，而不是冗长业务说明。  
对它来说，以下元素通常更有用：

- 主体
- 风格
- 色彩
- 材质
- 场景
- 光线
- 画幅参数

而“请你帮我生成一个如何如何的图片”这类口语指令价值不高。

### 7. 图像也可以作为提示的一部分

Midjourney 文档还强调，除了文本，还可以用图像参与提示。相关能力包括：

- Image Prompts：用图片影响内容、构图、色彩
- Style References：用图片影响风格气质
- Omni References / Character References：增强对象或角色一致性

因此，Midjourney 类工作流里，“文字 prompt + 参考图”通常比单纯文字更稳定。

## 适合沉淀到知识库的写法规范

### 基础短 prompt 模板

主体 + 核心动作/状态 + 风格 + 关键色彩

示例结构：

`古老灯塔，暴风雨海岸，电影感写实，冷蓝灰色调`

### 进阶 prompt 模板

主体 + 场景 + 构图 + 风格 + 光线 + 色彩 + 参数

示例结构：

`三只橘猫趴在旧书堆上，室内暖光，近景，彩铅插画，柔和阴影，--ar 3:2`

## 对知识库建设的价值

这篇资料最适合做“创意型 prompt 的入门基线”。它能帮助知识库回答下面几类问题：

- 为什么 prompt 不要写得像聊天指令
- 为什么短 prompt 常常更稳定
- 如何用更准确的词替代模糊词
- 什么时候该补细节，什么时候该保留开放性
- 为什么应优先描述想要的画面而不是反向否定
